## Шаг 1. Создать новый репозиторий

1. Войдите на github.com. Справа вверху «+» → **New repository**.
2. **Repository name** — например, `uchu-po-frp` (латиницей, без пробелов). Адрес сайта будет `https://<ваш-логин>.github.io/uchu-po-frp/`.
3. Отметьте **Public**. Галочки «Add a README», «.gitignore», «license» не ставьте.
4. Нажмите **Create repository**.

## Шаг 2. Загрузить сайт целиком

1. Распакуйте архив на компьютере: правой кнопкой по `uchu-po-frp-v5.6.zip` → **«Извлечь всё…»**. Появится папка `uchu-po-frp`.
2. Откройте эту папку. В ней: папки `api`, `css`, `data`, `js`, `proxy`, `vendor` и файлы `index.html`, `sw.js`, `README.md`, `vercel.json`, `.nojekyll`, `ИНСТРУКЦИЯ.md`, `ИЗМЕНЕНИЯ.md`. Файл `.nojekyll` скрытый: включите показ скрытых файлов (Windows: «Вид» → «Показать» → «Скрытые элементы»; Mac: Cmd+Shift+точка).
3. На странице нового репозитория нажмите ссылку **uploading an existing file**.
4. Выделите в папке **всё** (Ctrl+A) и **перетащите мышкой** в окно GitHub. Именно перетащите: так сохранятся папки.
5. Дождитесь, пока загрузятся все файлы (самый большой — `data/base.js`, около 3 МБ), и нажмите **Commit changes**.
6. Проверьте: в репозитории видны папки `api`, `css`, `data`, `js`, `proxy`, `vendor` и `index.html`, `sw.js` в корне. Если папок нет, а файлы лежат кучей — удалите репозиторий (Settings → внизу Delete this repository) и повторите, перетаскивая именно содержимое папки.

## Шаг 2а. Включить сайт

1. В репозитории: **Settings** → слева **Pages**.
2. **Source**: Deploy from a branch. **Branch**: `main`, папка `/ (root)`. **Save**.
3. Через 1–3 минуты сверху появится «Your site is live at …» — это адрес сайта. Откройте его и обновите страницу (Ctrl+F5).
4. Проверка: над кнопкой «Создать урок» есть рамка «Заметки к уроку», внизу страницы — ссылка «Режим разработчика».

Старый репозиторий можно оставить или удалить — новый от него не зависит.

## Шаг 3. Нейросеть: проще всего — OpenRouter

Прокси не нужен. Каждому учителю — один раз:

1. На сайте нажать **«⚙ ИИ»** вверху справа.
2. Нажать **«Войти через OpenRouter»**.
3. Войти на openrouter.ai (Google, GitHub или почта) и нажать «Authorize».
4. Сайт вернётся и сам сохранит ключ. Готово.

Бесплатные модели: до 20 запросов в минуту и 50 в день на аккаунт.

Если OpenRouter не ответит (лимит, сеть), сайт сам переключится на следующую подключённую нейросеть: Pollinations, DeepSeek, Gemini, затем GigaChat через Яндекс-функцию. На экране будет написано, какая и почему.

Перенести настройки на телефон: «⚙ ИИ» → «Другие устройства» → QR-код.

**GitHub Models подключить нельзя:** GitHub закрыл этот сервис 30 июля 2026 года.

**Pollinations по желанию.** Чтобы учителя входили в Pollinations одним кликом, зарегистрируйте приложение на enter.pollinations.ai/keys («Create New App Key», Redirect URI — адрес вашего нового сайта). Полученный ключ `pk_…` впишите в `index.html` в строку `pollinationsAppKey: ""`. Без этого учитель может вставить свой ключ `sk_…` вручную.

## Шаг 4. Яндекс-функция (GigaChat) — починить или оставить запасной

Почему не работало: функция отвечала `"cert": false`. У неё не было сертификата Минцифры, а без него Сбер не выдаёт токен. Новый `proxy.js` (версия 5) это исправляет: ищет сертификат сам, а если не найдёт, включает запасной режим, который разрешает сам Сбер.

1. console.yandex.cloud → **Cloud Functions** → ваша функция → **Редактор**.
2. Замените содержимое файла `proxy.js` текстом из `proxy/proxy.js` из архива. `yandex-function.js` не меняется.
3. Точка входа: `yandex-function.handler`. Таймаут — 120 секунд.
4. Переменные: `GIGACHAT_KEY` — ключ авторизации GigaChat. `ALLOW_ORIGIN` — адрес нового сайта без папки, например `https://<ваш-логин>.github.io`.
5. **Сохранить изменения.**
6. Проверка: откройте в браузере
   `https://functions.yandexcloud.net/d4ek0q8grbhn7q5muf24?path=/health` — должно быть `"version":5` и `"cert":true`.
   Затем `…?path=/diagnose` — должно быть `"ok":true`. Если нет, там будет точная причина: сертификат, блокировка IP, неверный ключ, scope или оплата.

Ещё надёжнее — положить сертификат в функцию файлом: скачайте его с https://www.gosuslugi.ru/crt (корневой сертификат), назовите `russian_trusted_root_ca.pem` и добавьте третьим файлом рядом с `proxy.js`.

На сайте: «⚙ ИИ» → «GigaChat через Яндекс-функцию» → **«Проверить функцию и Сбер»**.

## Шаг 4а. Картинки из Яндекса для презентаций

Под каждым слайдом сайт показывает «Картинки Яндекса к этому слайду»: поиск сам предлагает картинки по теме слайда, а вы решаете, какую вставить. Потом картинку можно обрезать, заменить, сделать фоном, передвинуть.

Браузер не может обращаться к поиску Яндекса напрямую, поэтому запросы идут через ту же Яндекс-функцию (прокси). Нужен API-ключ Yandex Search API:

1. console.yandex.cloud → ваш каталог → **Сервисные аккаунты** → **Создать**. Роль: `search-api.webSearch.user`.
2. Откройте этот сервисный аккаунт → **Создать новый ключ** → **API-ключ** (область `yc.search-api.execute`). Скопируйте ключ.
3. ID каталога — на главной странице каталога (строка вида `b1g…`).
4. В Яндекс-функции добавьте переменные: `YANDEX_SEARCH_KEY` — ключ, `YANDEX_SEARCH_FOLDER` — ID каталога. Сохраните.
5. Проверка: `…?path=/health` — должно быть `"images":true`.

Поиск Yandex Search API платный (тарифы — в консоли Yandex Cloud, обычно хватает стартового гранта). Пока ключа нет, сайт показывает картинки Википедии и Викисклада, а кнопка «Открыть в Яндексе ↗» открывает Яндекс Картинки: картинку можно скопировать и вставить на слайд через Ctrl+V.

## Шаг 5. Прокси — крайняя мера

Нужен, только если из сети школы не открываются зарубежные нейросети. Автоматически сайт прокси не ищет и не просит.

- Запустите `proxy/proxy.js` на своём сервере (Node.js 18+). Логин и пароль — переменные `PROXY_USER` и `PROXY_PASS`. Сайту нужен HTTPS (nginx или Caddy).
- На сайте: «⚙ ИИ» → «Прокси — крайняя мера» → адрес, порт, логин, пароль. Галочка **Split Tunneling**: российские сервисы идут напрямую, зарубежные — через прокси. Затем «Проверить подключение».

Учитель нажимает «Материалы» → «Отправить материалы разработчику». Файл с новыми материалами уходит на pedagogruslit@gmail.com, тема «Методические наработки для сайта». Отправляет бесплатный сервис форм FormSubmit: статический сайт сам письма слать не умеет.

**Один раз:** после первой отправки на pedagogruslit@gmail.com придёт письмо от FormSubmit — нажмите в нём кнопку подтверждения. Файлы, отправленные до подтверждения, не сохраняются, поэтому первую отправку сделайте сами, пробную.

Если почта не ответит, файл сам скачается на компьютер учителя и откроется письмо, к которому его останется приложить.

## Шаг 7. Режим разработчика

Внизу любой страницы — ссылка **«Режим разработчика»**. Пароль: `pedagogural`. Пароль каждый раз вводится заново. Кнопка «Заполнить вход» подставляет его, если вы разрешили браузеру запомнить. Выход — кнопка «Выйти» вверху.

Что там есть:

- **Материалы** — вся база, в том числе встроенная. Кнопка «Скачать новый extra.js».
- **Конструктор упражнений** — все упражнения с типами, темами и классами.
- **Конспекты** — уроки-образцы, которые система выделила из файлов: структура и вопросы.
- **ФРП** — что встроено и как встроить.
- **Файлы от пользователей** — загрузите пакеты из почты (можно несколько сразу, повторы не добавятся). Можно открыть, посмотреть структуру урока и встроить.
- **Черновики, Логи, Отчёты.**

**Публикация без ручной загрузки на GitHub (настроить один раз).** Режим разработчика → «Материалы» → блок «Публикация на сайт»:

1. На github.com: аватар → **Settings** → **Developer settings** → **Personal access tokens** → **Fine-grained tokens** → **Generate new token**.
2. Repository access: **Only select repositories** → репозиторий сайта. Permissions → Repository permissions → **Contents: Read and write**. **Generate token**, скопируйте его (начинается с `github_pat_`).
3. Вставьте токен в поле «Токен GitHub» (логин и имя репозитория подставятся сами) → **«Сохранить и проверить доступ»**. Должно появиться «✓ Доступ есть».

После этого всё работает само: в режиме разработчика перетащите файлы в «Загрузить и встроить для всех» — они очистятся, разложатся по классам и темам и сразу сохранятся в `data/extra.js` репозитория. То же с ФРП (`data/frp.js`) и с файлами от пользователей (кнопка «Встроить в базу»). Через 1–2 минуты обновление появится на сайте у всех учителей, а система переучится на новых материалах при следующем открытии сайта. Токен хранится только в вашем браузере.

Без токена всё работает по-старому: файл скачивается, и его нужно загрузить в папку `data` на GitHub вручную.

## Шаг 8. ФРП — уже встроена

Ничего делать не нужно: файл `data/frp.js` в архиве. В нём четыре программы, которые вы прислали, перенесены дословно:

| Программа | Что есть |
|---|---|
| Русский язык, 5–9 кл. (2025) | личностные, метапредметные, предметные результаты по классам; тематическое планирование с программным содержанием и видами деятельности; поурочное планирование (170 / 204 / 136 / 102 / 102 урока) |
| Литература, 5–9 кл. | результаты; тематическое планирование по классам (произведения, часы, содержание, виды деятельности) |
| Русский язык, 10–11 кл. | результаты; тематическое планирование |
| Литература, 10–11 кл. (базовый) | результаты; тематическое планирование |

На сайте список тем (стрелка ▾ у поля «Тема») идёт по ФРП: по русскому 5–9 — по урокам, остальное — по темам планирования. В техкарту дословно подставляются результаты и блок «Тематическое планирование ФРП».

Если выйдет новая редакция программы: режим разработчика → «ФРП» → «Загрузить файл программы» (PDF с текстом или .docx) → «Встроить для всех».

## Шаг 9. Сканы

Часть встроенных файлов — сканы без текста: рабочие тетради 5, 7, 8 кл., учебники и книги для учителя Сухих, журнал, «Я иду на урок», «Парус и шёпот». В режиме разработчика → «Материалы» → **«Распознать скан (OCR)»** выберите PDF. Распознавание идёт прямо в браузере, несколько минут на книгу. Потом «Скачать новый extra.js» и загрузите его в `data`.

Планы-конспекты Фефиловой (10 и 11 кл.) в прошлой выгрузке обрезались на 400 000 знаках, примерно на середине книги. Теперь предел 2 000 000. Если загрузить эти PDF заново, встроятся целиком.

## Авторские права

Рабочие тетради, учебники и пособия — изданные книги, у них есть правообладатели. В открытом репозитории их текст может прочитать кто угодно, даже если на сайте он виден только разработчику. Перед публикацией решите, допустимо ли это в вашем случае.

## Как обновлять дальше

Заменяйте файлы в репозитории новыми: «Add file» → «Upload files» → перетащить → «Commit changes». Уроки и материалы учителей не пропадут: они хранятся в браузерах. Ручные правки учителей не перезаписываются.
