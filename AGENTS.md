# Codex: инженерные задачи проекта «Учу по ФРП»

Codex работает **только с инженерной частью**. Он не придумывает учебные тексты,
не переписывает конспекты и **не занимается генерацией изображений**. Любые задачи
про картинки, SVG и плакаты — вне этого файла.

## Контекст

- Сайт: `https://uchu-po-frp.ru/`, статический JS, Supabase, Yandex Cloud.
- Встроенная ФРП: 21 предмет, **5 694 урока** в `knowledge/frp/`.
- Конфиги изображений: `config_claude.json`, `config_chatgpt.json` — это данные,
  не задача Codex.
- Внутренняя база `knowledge-base/` ~450 МБ; в публичную выкладку не входит.
- `knowledge/` (уроки и база знаний) — внутреннее, исключено из деплоя.
- `deploy-yandex.yml` уже использует `--size-only` и исключает `knowledge-base/*`,
  `knowledge/*`.
- Тесты: `_stage/lead-func.mjs`, `_stage/lead-smoke.mjs`, `_stage/uchu-check.mjs`.
- Открытые инженерные долги: старые `render_*` workflow, проверка всех выгрузок,
  Supabase/152-ФЗ, SMS, безопасность, производительность.

## Жёсткие ограничения

1. Не менять учебные тексты и не генерировать их.
2. Не трогать `knowledge-base/`, `knowledge/frp/`, `frp_tasks/` без прямой задачи.
3. Не делать `git add .`.
4. Не выкладывать `knowledge-base/` и `knowledge/` в Object Storage.
5. Не менять `deploy-yandex.yml` без необходимости.
6. Не добавлять платные API и внешние сервисы без явного разрешения.
7. Не сообщать «готово», пока тест или артефакт реально не подтверждён.
8. Сначала аудит и отчёт, потом изменения.

## Приоритет P0 — сначала это

### 1. Аудит репозитория и CI
- `git status`, все workflow, что реально делает каждый.
- Найти мёртвые/дублирующиеся `render_*` workflow, которые не нужны сайту.
- Проверить, что деплой не загружает `knowledge-base`/`knowledge` каждый раз.
- Показать отчёт до удаления/изменения.
- После отчёта отключить лишнее, не ломая `deploy-yandex.yml`.

### 2. Матрица выгрузок
Автоматически проверить все форматы:
- конспект, техкарта, рабочий лист, контроль, памятка, ДЗ — DOCX и PDF;
- презентация — PPTX и PDF;
- рабочий лист — PNG (2 страницы);
- ZIP.

Проверять:
- файл создаётся, размер > 0, открывается;
- PDF/PNG не падают на CSS-цветах;
- в конспекте есть **упражнения**, а не только теория;
- техкарта — две таблицы;
- финальный слайд теста — QR без ссылки.

### 3. Данные и ссылки
- Проверить 5 694 папки уроков: `lesson.json` валиден, `index.html` существует.
- Проверить `config_claude.json` (2 270 уроков) и `config_chatgpt.json` (3 006):
  JSON валиден, нет битых `lesson_id`.
- Проверить manifest и ссылки; не должно быть 404 на существующие уроки.
- Создать отчёт о пропусках и битых ссылках.

### 4. Стабильность сайта
- Прогнать smoke-тесты, проверить консоль на ошибки.
- Убрать мёртвые кнопки/старые ID после последних изменений.
- Проверить мобильный макет и доступность основных страниц.
- Не переделывать дизайн без запроса.

### 5. Безопасность
- Проверить, что ключи Supabase/прокси не попадают в клиент.
- Проверить RLS-политики и доступ к чужим урокам/результатам.
- Проверить, что публичные страницы не раскрывают внутреннюю базу.

## Приоритет P1 — после P0

### 6. Supabase и 152-ФЗ
- Подготовить перенос на self-hosted Supabase в РФ.
- Проверить auth, Яндекс ID, SMS-хук, профили, уроки, тесты.
- Без доступа к Яндекс Облаку и базе — только план, скрипты и проверки,
  без ложного «перенесено».

### 7. Производительность
- Ленивая загрузка тяжёлых данных, кеш, service worker.
- Размер JS/CSS, скорость первой загрузки.
- Не ломать офлайн-режим.

### 8. Платежи и юридические страницы
- Проверить платёжный поток, чеки, возвраты.
- Не менять юридические тексты без владельца.

## Что Codex не делает

- Не генерирует картинки, SVG-плакаты и «настоящие иллюстрации».
- Не пишет конспекты и упражнения из памяти.
- Не меняет тексты таблиц.
- Не загружает базу знаний повторно.
- Не изображает фоновые процессы, которых нет.

- [ ] Матрица выгрузок проходит.
- [ ] Конспекты с упражнениями, техкарты с двумя таблицами.
- [ ] 5 694 урока: JSON и страницы валидны.
- [ ] Нет ошибок JS на основных страницах.
- [ ] Деплой не тянет `knowledge-base`/`knowledge`.
- [ ] Отчёт: что изменено, какие команды проверены, что осталось.
