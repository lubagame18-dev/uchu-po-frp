# Codex: правила работы и рабочие задачи

Этот файл читает Codex при старте. Работаем в репозитории `uchu-po-frp`.
Главный принцип: **Codex делает инженерную часть**, а не придумывает учебные тексты и не изображает художника.

## Что уже есть

- `frp_tasks/ru.json` — 267 уроков русского языка, 469 слотов изображений.
- У каждого урока есть `images[]` с `order`; на один урок может быть 2–3 изображения.
- `frp_tasks/*.json` — задания ChatGPT по предметам.
- `knowledge-base/` — полная внутренняя база, около 450 МБ.
- `knowledge/frp/` — 5 694 урока: папки, `lesson.json`, страницы.
- `knowledge/` — внутренняя база знаний, **не публикуется** на сайте.
- `deploy-yandex.yml` уже исключает `knowledge-base/*` и `knowledge/*`, использует `--size-only`.
- Старые `presentation_database/render_*.py` и `render_*.yml` генерировали SVG/таблицы и **не являются** настоящими иллюстрациями.

## Жёсткие ограничения

1. **Никакого OpenAI API, DALL-E, внешних платных сервисов и сетевой генерации картинок.**
2. Не выдавать SVG/таблицы/шаблонные карточки за готовые иллюстрации.
3. Не придумывать учебный текст. Брать только из `frp_tasks/ru.json` и готовых таблиц.
4. Не менять существующие тексты таблиц и не переписывать конспекты.
5. Не делать `git add .`.
6. Не коммитить и не выгружать `knowledge-base/`, `knowledge/frp/`, `frp_tasks/` целиком.
7. Не запускать `aws s3 sync` и не менять `deploy-yandex.yml` без необходимости.
8. Не создавать «фоновые процессы», которые существуют только в отчёте. Работа либо выполнена, либо нет.
9. Не обещать «469 готово», пока `audit` не покажет 469/469.

## Что делать лучше всего (рабочие задачи)

### P0. Аудит и порядок
1. Проверить `git status`, не потерять незакоммиченные изменения.
2. Перечислить все workflow в `.github/workflows` и что каждый реально делает.
3. Найти workflow, которые создают SVG/таблицы и выдают их за иллюстрации.
4. Показать отчёт до удаления/изменения.
5. После отчёта отключить/удалить старые `render_*`, которые не нужны, не трогая `deploy-yandex.yml`.

### P0. Генератор плакатов без API
Создать `tools/ru-visuals/`:

- `generate.py` — читает `frp_tasks/ru.json`, создаёт PNG 1600×900 или 1280×720;
- `renderer.py` — Pillow/HTML, книжная редакционная вёрстка;
- `state.json` — не пересоздавать готовое;
- `manifest.json` — `lesson_id`, `grade`, `topic`, `order`, `file`, `sha256`, `width`, `height`, `source`, `caption`, `status`;
- `contact_sheet.py` — общий лист для проверки.

Правила:
- имя строго `<lesson_id>-<order>.png`;
- путь `visuals/ru/out/grade-<grade>/`;
- текст накладывается кодом из `ru.json`, а не нейросетью;
- один слот = один файл;
- текст не вылезает за рамки;
- если текста нет — только `topic` и `caption`, без выдуманных правил;
- стиль — по 4 референсам, которые пользователь положит в `visuals/ru/assets/style/`.

Команды:
```bash
python tools/ru-visuals/generate.py --dry-run
python tools/ru-visuals/generate.py --limit 10
python tools/ru-visuals/generate.py --lesson ru-1-001
python tools/ru-visuals/generate.py --audit
```

### P1. MCP-плагин
Создать `mcp/ru-visuals/server.py` с tools:
- `ru_visuals_status`
- `ru_visuals_next`
- `ru_visuals_render`
- `ru_visuals_batch`
- `ru_visuals_audit`
- `ru_visuals_contact_sheet`
- `ru_visuals_publish`

`publish` добавляет в git **только новые/изменённые файлы** из `visuals/ru/`.

### P1. Сайт
- Подключить manifest к странице урока: несколько изображений по `order`.
- Слева рамка, справа текст; ничего не выдумывать.
- Не менять выгрузки Word/PDF/PPTX и существующий конструктор без необходимости.

### P1. Проверки
- 267 уроков / 469 слотов.
- Каждому `lesson_id+order` — один PNG.
- Нет пустых, битых, дублей по SHA-256.
- `manifest` ↔ `state`.
- Contact sheet после первой партии 10–20 изображений.

### P2. После проверки
- Только после contact sheet и отчёта — следующие партии.
- Не коммитить больше 20–30 новых PNG за раз без проверки.
- В конце отчёт: что сломано, что создано, сколько осталось, какие команды запускались.

## Что Codex не делает

- Не генерирует «настоящую живопись» без локальной image-модели.
- Не пишет учебные тексты из памяти.
- Не подменяет рисунки таблицами.
- Не загружает базу знаний заново.
- Не делает вид, что задача выполнена, если файлов нет.

## Definition of Done

- [ ] Старые фейковые workflow отключены/удалены.
- [ ] `--dry-run` показывает 469 слотов.
- [ ] Первая партия 10–20 PNG лежит в `visuals/ru/out/`.
- [ ] `audit` проходит.
- [ ] Contact sheet собран.
- [ ] Текст не изменён.
- [ ] В git попали только новые файлы `visuals/ru/`.
