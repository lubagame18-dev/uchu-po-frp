# Перенос в Россию: Supabase на Яндекс Облаке

Цель — персональные данные пользователей (имя, телефон, школа, город, фото, уроки)
хранить в Российской Федерации, а не в зарубежном Supabase Cloud. Это требование
локализации по 152-ФЗ.

**Важно:** этот набор — установочный комплект. Создать виртуальную машину и перенести
данные за вас можно только при наличии доступа к вашему аккаунту Яндекс Облака
(или SSH к уже созданной ВМ) и строки подключения к текущей базе Supabase.

## Что понадобится

- Аккаунт Яндекс Облака и платёжный аккаунт.
- Домен `uchu-po-frp.ru` (DNS уже в Яндекс Cloud DNS).
- Виртуальная машина: **Ubuntu 22.04, 4 vCPU, 8 ГБ RAM, 50–100 ГБ SSD** (Supabase
  в Docker требует памяти; 2 ГБ мало).
- Поддомен `api.uchu-po-frp.ru` — A-запись на IP машины.
- Ключи SMS-провайдера (sms.ru или smsc) для входа по номеру.
- Доступ к текущей базе Supabase для выгрузки данных (строка подключения).

## Шаг 1. Создать ВМ в Яндекс Облаке

Консоль → Compute Cloud → Создать ВМ:
- образ Ubuntu 22.04 LTS;
- 4 vCPU, 8 ГБ RAM, 50 ГБ SSD;
- публичный IP;
- SSH-ключ (свой публичный ключ).

В DNS Яндекса добавьте A-запись:
`api` → публичный IP машины.

## Шаг 2. Запустить установку на машине

Скопируйте папку `deploy/ru` на машину (или выполните команды из неё) и запустите:

```bash
sudo DOMAIN=api.uchu-po-frp.ru \
     EMAIL=ваш@email.ru \
     DASHBOARD_PASSWORD='сложный-пароль' \
     bash bootstrap-vm.sh
```

Скрипт:
1. ставит Docker, Git, Caddy;
2. скачивает официальный self-hosted Supabase (папка `docker` проекта Supabase);
3. генерирует пароли, JWT-секрет и ключи `anon` / `service_role`;
4. поднимает Supabase;
5. настраивает HTTPS на `api.uchu-po-frp.ru` через Caddy;
6. выводит адрес API и ключи — их нужно вписать в сайт.

Проверка:
```bash
curl https://api.uchu-po-frp.ru/auth/v1/health
curl https://api.uchu-po-frp.ru/rest/v1/
```

## Шаг 3. Переключить сайт на новый API

В `index.html` в `UCHU_SITE.cloud` замените:

```js
cloud: {
  url: "https://api.uchu-po-frp.ru",
  anonKey: "НОВЫЙ_ANON_KEY"
}
```

Затем задеплойте сайт (GitHub Actions) и проверьте вход/регистрацию.

## Шаг 4. Перенести данные

Смотрите `migrate.md`. Порядок:
1. Выгрузить `public`-таблицы (`profiles`, `user_info`, `lessons`, `quizzes`,
   `quiz_results`, `payments`, `ai_keys` — если есть) из старого Supabase.
2. Залить в новый Supabase.
3. Пользователей перенести отдельно: либо через `pg_dump` схемы `auth`, либо
   попросить войти заново (пароли не покидают Supabase).

## Шаг 5. Вход по телефону (SMS)

1. В новом Supabase: Authentication → Providers → Phone — включить.
2. В Яндекс-функции задать переменные:
   - `SMS_HOOK_SECRET` — секрет хука из Supabase;
   - `SMS_API_ID` (sms.ru) или `SMS_LOGIN`/`SMS_PASSWORD` (smsc);
   - `SMS_SENDER` — имя отправителя;
   - `SMS_DAILY_MAX=300`.
3. Загрузить `uchu-function.zip` в Яндекс Облако.
4. В Supabase → Auth Hooks → Send SMS указать:
   `https://functions.yandexcloud.net/d4ek0q8grbhn7q5muf24?path=/sms-hook`
   и тот же секрет.
5. Проверить SMS на МТС, Билайн, МегаФон, Т2.

## Шаг 6. Перед публикацией

- Уведомление в Роскомнадзор об обработке персональных данных.
- Политика конфиденциальности и согласие с телефоном/SMS/данными детей.
- Договор с SMS-провайдером и хостингом (поручение на обработку ПД).
- Резервные копии PostgreSQL и мониторинг.
- Проверить удаление аккаунта и выгрузку данных по запросу.
- Платежи: чеки по 54-ФЗ (если платно).

## Стоимость ориентировочно

- ВМ 4 vCPU / 8 ГБ — порядка нескольких тысяч рублей в месяц.
- Диск 50–100 ГБ — отдельно.
- SMS — по тарифу провайдера (несколько рублей за сообщение).
- Резервные копии — место в Object Storage.

Точные цены смотрите в калькуляторе Яндекс Облака: тарифы меняются.

## Ограничения

- Скрипт не создаёт ВМ и DNS за вас: для этого нужны доступ к аккаунту и SSH.
- Перенос `auth.users` с паролями требует доступа к базе; без него пользователи
  регистрируются заново (данные уроков можно перенести отдельно).
- Юридическую часть (уведомление РКН, тексты согласий) должен проверить юрист.
