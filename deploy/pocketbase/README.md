## Что остаётся как есть

- uchu-po-frp.ru, статика и сертификат — Яндекс Object Storage/Cloud DNS.
- Публикация сайта — существующий GitHub Actions.
- AI-прокси и платёжные webhook — существующая Yandex Cloud Function.
- Учебные тексты, генератор, оформление и экспорт не переписываются.

PocketBase обслуживает вход по email/паролю, SMS и Яндекс ID, профиль, уроки, связанные результаты,
права доступа и серверные данные тарифов/лимитов. По скриншоту владельца видны
бакеты и функция, но отдельная Compute Cloud VM на показанном экране не видна.
Бакет и Cloud Function не предоставляют постоянный процесс/SQLite-диск PocketBase.
До наличия подходящего места запуска продолжаются локальные проверки.

## Устройство и ограничения

Закреплён PocketBase **0.40.6**. `pb_migrations/` создаёт auth-коллекцию uchu_users
и закрытые коллекции данных. В обычном REST PocketBase они недоступны пользователям.
`pb_hooks/` предоставляет ограниченный адаптер существующих Auth/PostgREST-вызовов
на `/api/uchu/`. Не поддерживает произвольный SQL, JOIN и произвольные фильтры.
Внутри коллекций сохраняются исходные JSON-поля, внешние lesson/quiz/order ID.
Права проверяются адаптером, включая владельца при upsert; фильтры не подставляются
в SQL. Запись пачки, начисление платежа, списание лимита и удаление quiz с дочерними
записями выполняются транзакциями SQLite.

Чтение ограничено 10 000 записей на коллекцию/владельца. При превышении возвращается
явная ошибка вместо усечения; до роста нужна серверная пагинация/оптимизация.
Большие файлы из Supabase Storage требуют отдельного переноса: exporter
отказывается молча пропускать существующие Storage objects.

Публичные образовательные коллекции base_materials/site_rules сохраняют существующий
режим чтения. Приватные уроки, профили и результаты открываются только владельцу,
секретные коллекции — только серверу. Права разработчика определяются site_admins,
не user_metadata. Публичная отправка результата ограничена размером/полями и
существующим quiz; достоверность самого балла этим переносом не сертифицируется.

**Обязательные способы входа:** email, SMS и Яндекс ID. SMS/PKCE и безопасная привязка
реализованы и проверены локально с имитацией провайдеров; реальная приёмка ещё нужна.
**Ещё не реализованы/не приняты:** Google/прочие OAuth, magic links для ботов,
старые интерактивы без quiz ID (lesson_results_get),
автосписания по подпискам. Адаптер возвращает явную ошибку, не обращается к старой
БД в качестве запасного варианта. Их нужно реализовать/проверить или согласованно
выключить до переключения. Нельзя считать проект полностью перенесённым, пока
обязательные для владельца сценарии не пройдены.

## Подготовка сервера (делает Codex после доступа)

PocketBase — не облачный аккаунт: это процесс с постоянным диском. Нужны endpoint
HTTPS, persistent storage в РФ, резервное копирование и проверка восстановления.
Конкретный тариф до 500 ₽ здесь не обещается; сначала проверяется полный счёт,
включая диск/IP/бэкап, и фактическая нагрузка. ОС/архитектуру целевого сервера
проверить: fetch-binary.py сейчас скачивает Linux amd64.

```bash
# Только на сервере; пути вне публичного checkout. Команды выполняет Codex.
python3 deploy/pocketbase/create-server-env.py \
  --file <PRIVATE_DIR>/pocketbase.env --data-dir <PERSISTENT_RF_DIR>/pb_data
python3 deploy/pocketbase/run.py --env-file <PRIVATE_DIR>/pocketbase.env \
  --binary <PATH_TO_PINNED_POCKETBASE>
```

Секреты генерируются один раз, не печатаются, файл 600. PB_SETTINGS_KEY шифрует
настройки, но не весь SQLite-диск: шифрование диска/бэкапа настраивается отдельно.
Ключ необходимо сохранить вместе с защищённой резервной копией. Повторное создание
файла запрещено. Пример HTTPS-прокси — Caddyfile.example; админка снаружи закрывается,
доступ Codex получает через локальный туннель. При managed-размещении эти команды
заменяются конфигурацией платформы, которую ещё предстоит проверить.

Настроить SMTP через защищённую админку, проверить доставку, SPF/DKIM/DMARC и
восстановление. `UCHU_ALLOW_SIGNUP` по умолчанию false; включить только после проверки.
Письма ведут на `accounts-confirm.html` существующего сайта, а не публичную админку.
URL приложения в PocketBase settings.meta.appURL — https://uchu-po-frp.ru.
Регистрация: минимум 8 символов пароля. PB access-токен живёт до 14 дней, может
обновляться, пока действителен; после истечения нужен повторный вход. Локальный
выход очищает текущую сессию браузера; не выдаётся за отзыв всех токенов на устройствах.

## Подготовка исходных данных

Владелец сообщил, что пользователей пока нет, но фактическая исходная база ещё
не проверена. Нельзя автоматически считать её пустой или удалять аккаунт владельца.
Сначала сделать полный защищённый бэкап источника; существующий комплект
`deploy/supabase-rf/` содержит команды исходного Supabase export, не команды установки PB.

```bash
umask 077
# Пароль в .pgpass/защищённом env, не в истории команд; каталог зашифрован и в РФ.
psql -X -qAt "$SOURCE_DB_URL" -v ON_ERROR_STOP=1 \
  -f deploy/pocketbase/export-accounts.sql > <PRIVATE_DIR>/accounts.json
python3 deploy/pocketbase/import-supabase.py <PRIVATE_DIR>/accounts.json
```

Exporter читает источник в согласованной read-only транзакции. Не экспортирует
пароли/токены сессий, но включает ПД и серверные ключи в application rows:
JSON никогда не публиковать и не коммитить. Неизвестные public-таблицы или Storage
objects блокируют экспорт до инвентаризации, а не исчезают при переносе.

Импорт по умолчанию только dry-run. После backup и проверки пустоты target:

```bash
# POCKETBASE_URL и POCKETBASE_SERVICE_TOKEN — защищённые серверные переменные.
python3 deploy/pocketbase/import-supabase.py <PRIVATE_DIR>/accounts.json \
  --apply --empty-target-confirmed
```

Существующие email-аккаунты блокируют импорт без отдельно согласованного `--allow-password-reset`.
Подтверждённые РФ мобильные номера переносятся как SMS-идентичности, включая
аккаунты без email. Неподтверждённый номер или сочетание подтверждённого номера
с неподтверждённым email блокирует импорт до отдельного плана.
Не обещаем перенос прежних паролей. Эта опция создаёт случайные неизвестные пароли
и требует проверенного email recovery; не рассылает письма автоматически.
Связи владельцев отображаются по source UUID → PB ID, старый UUID хранится в legacy_id.
Lesson/quiz/order ID сохраняются. Неподтверждённые почты не превращаются в подтверждённые.
Сбой импорта означает остановку: восстановить чистый target из snapshot, разобраться,
повторить пробный перенос. Повторный импорт в непустой target запрещён; частичный
результат не считается миграцией. После импорта сверить counts, ID, владельцев,
содержимое и действительные сценарии; исходную БД этот инструмент не меняет.

## Яндекс-функция остаётся в Яндексе

Код proxy/accounts-backend.js переключает только запросы кабинетов, не AI и не
платёжные API. Для PocketBase в **серверных секретах** функции задать:

- ACCOUNTS_BACKEND=pocketbase
- POCKETBASE_URL=https://<ACCOUNTS_DOMAIN>
- POCKETBASE_SERVICE_TOKEN=<тот же UCHU_SERVICE_TOKEN, только в секрете функции>

Загрузить новый код функции с этим модулем, сохранив остальные секреты и настройки.
Существующий uchu-function.zip этим изменением не пересобран и не развёрнут:
перед live-проверкой собрать ZIP из актуальных proxy/*.js, проверить состав.
Не помещать service token в index.html, accounts-config.js или пульт.
Старые env сохранить защищённо для отката. Продамус/ЮKassa тестируются в sandbox.
Для PB начисление выполняется только по сохранённому заказу, сумма должна совпадать;
изменение баланса и paid фиксируются одной транзакцией. Неизвестный order или сбой
возвращает ошибку для повторной обработки, а не создаёт непроверенное начисление.

## Переключение — только после приёмки

```bash
python3 deploy/pocketbase/switch-accounts.py --url https://<ACCOUNTS_DOMAIN>
# Без --write только проверка, ничего не меняется.
```

Заполнить acceptance.example.json результатами **реальных** тестов с указанием
артефактов в отчёте. Галочки на странице-пульте не подменяют этот отчёт.
Переключатель требует все gates=true и сохранит локальные копии в work/pocketbase-cutover/:

```bash
python3 deploy/pocketbase/switch-accounts.py --url https://<ACCOUNTS_DOMAIN> \
  --write --acceptance-report <PRIVATE_DIR>/acceptance.json
```

Меняет account config основной/тестовых страниц, сохраняет включённый SMS-флаг. Домен сайта,
AI-прокси и cloud не меняет. Gates `sms_login`, `yandex_login`, `identity_linking`
обязательны: владелец потребовал сохранить эти методы, отключать их нельзя.
Старые вкладки могут исполнять старый JS: до финального snapshot остановить записи
в исходную БД и проверить запрет, обновить service worker и проверить свежий браузер.

При смене backend старые сессии не отправляются в новую БД. Не принадлежащие новому
аккаунту локальные уроки архивируются в отдельной IndexedDB uchu-account-archives,
перед очисткой проверяется запись архива; после logout архив сохраняется.
Это сохраняет черновики, но не раскрывает их в другом аккаунте и не отправляет на сервер. Материалы и изображения того же владельца восстанавливаются при повторном входе; архивные уроки автоматически не перезаливаются, чтобы не воскресить удалённые на другом устройстве записи. В кабинете есть кнопка «Копия локальных уроков» для своего последнего архива.
Сопоставленный legacy_id позволяет тому же мигрированному владельцу сохранить синхронизацию.
Извлечение локального архива выполняется только после проверки владельца; автоматически
прикреплять архивы к произвольному новому аккаунту запрещено.

## Backup/restore и откат

```bash
# Сначала остановить PocketBase, путь хранения — зашифрованный и в РФ.
PB_DATA_DIR=<DATA> PB_BACKUP_ROOT=<ENCRYPTED_RF_BACKUP_DIR> PB_IS_STOPPED=yes \
  bash deploy/pocketbase/backup.sh
PB_RESTORE_FROM=<SNAPSHOT_DIR> PB_RESTORE_TO=<NEW_EMPTY_DATA_DIR> PB_IS_STOPPED=yes \
  bash deploy/pocketbase/restore.sh
```

Скрипты проверяются на реальном тестовом SQLite. Restore не перезаписывает каталог,
backup не размещается внутри БД. Признак PB_IS_STOPPED — подтверждение оператора,
а не автоматическое обнаружение процесса: Codex проверяет остановку отдельно.
Для online backup использовать штатный PocketBase backup API после отдельной проверки.
Сохранить также hooks, migrations, точную версию и ключ шифрования настроек.
При смене версии сначала восстановление на тесте; auto-update в эксплуатации не включать.

Откат: остановить новые записи, сохранить PB backup, сверить дельту новых уроков/
платежей, вернуть публичные config-файлы и серверные env Яндекс-функции в одно окно.
Простой возврат старой базы после новых записей теряет данные, поэтому не выполняется
автоматически. Старый Supabase и исходные бэкапы не удалять до подтверждённого restore.

## SMS и Яндекс ID — обязательная настройка перед переключением

08.11.2026 владелец подтвердил сохранение SMS и Яндекс ID. Принудительного
выключения телефона больше нет. Секреты находятся только в защищённом env сервера
PocketBase; не в index.html, START.html или GitHub.

- SMS: для первого подключения выбран вариант подготовки SMSPILOT с общим именем
  (`SMS_PROVIDER=smspilot`, `SMSPILOT_API_KEY`), см. [план и официальные ссылки](SMS_SETUP.md).
  Также поддерживаются SMS.RU (`SMS_PROVIDER=smsru`, `SMS_API_ID`) либо СМСЦ
  (`SMS_PROVIDER=smsc`, `SMS_LOGIN`, `SMS_PASSWORD`); необязательный `SMS_SENDER`.
  Владелец подтвердил отсутствие SMS-сервиса: новый аккаунт создаёт владелец,
  а Codex готовит интеграцию. Оплату и условия нужно согласовать до реальной отправки.
- `SMS_DAILY_MAX=30` по умолчанию: общий суточный предел числа запросов; до включения
  согласовать число с владельцем. На номер максимум 6 запросов в сутки, на IP 10/час;
  повтор не чаще минуты. Код из 6 цифр действует 5 минут, не больше 5 попыток.
  Хранится только HMAC, проверка/погашение атомарные; счётчики переживают рестарт.
- Яндекс: `YANDEX_CLIENT_ID`, `YANDEX_CLIENT_SECRET`,
  `UCHU_SITE_ORIGIN=https://uchu-po-frp.ru`; точный Redirect URI в существующем
  приложении: `https://uchu-po-frp.ru/yandex.html`. Разрешения `login:email login:info`.
  Официальные панели: https://oauth.yandex.ru/ и https://console.yandex.cloud/.
- После настройки и тестов: `UCHU_ALLOW_SMS=true`, `UCHU_ALLOW_YANDEX=true`;
  для новых пользователей отдельно `UCHU_ALLOW_SMS_SIGNUP=true` и
  `UCHU_ALLOW_YANDEX_SIGNUP=true`. Все флаги в созданном env исходно false.
  SMTP проверяется отдельно для email-регистрации и recovery.
- OAuth state и S256 PKCE связаны с текущей вкладкой и серверным challenge на 5 минут.
  State одноразовый; при сбое провайдера нужно начать вход заново. Авторизационный
  код убирается из URL до сетевых запросов; токены не передаются в URL.
- Повторный вход Яндекса ищет стабильный provider ID. Совпадение почты не объединяет
  аккаунты. Для уже существующего кабинета: войти прежним способом → профиль →
  «Привязать Яндекс ID» / «Привязать телефон» и пройти подтверждение.
  Смена уже связанного идентификатора требует отдельного сценария восстановления.
- Старый Яндекс-вход создавал аккаунты по email без стабильного provider ID. До
  приёмки реальную исходную базу нужно проверить: таким владельцам может требоваться
  первый вход через проверенную почту и явная привязка. Автоматически объединять их
  по одному адресу нельзя. Для переноса имеющихся phone accounts сохраняется номер,
  новый пароль SMS-пользователю без email не нужен.

`test-identities.py`: настоящий PocketBase/SQLite, временная копия hooks с локальной
имитацией внешних провайдеров. Production hooks не содержат test mode или URL override.
`test-identity-providers.cjs` проверяет реальные адаптеры: фиксированные HTTPS URL,
POST вместо секретов в query string, статусы получателя, PKCE и отказы.
При `POCKETBASE_BROWSER=1` выполняются кнопка Яндекса → callback → кабинет, SMS-форма,
отказ неверного state. Это не доказательство доставки настоящего SMS или настройки
настоящего приложения Яндекса. После доступа обязательны такие же тесты с провайдерами.

08.11.2026 добавлен месячный предел `SMS_MONTHLY_MAX=20` (число запросов, не рубли).
Проверка SMSPILOT без отправки: `check-smspilot.py`; тест `test-sms-setup.py`.
Владелец выбрал один новый кабинет; пять личных аккаунтов остаются в Supabase.
Импорт пользователей не выполняется. Отдельный VPS планируется в SpaceWeb либо REG.RU;
домен зарегистрирован у SpaceWeb, но DNS по действующей делегации обслуживает Яндекс.

`python3 deploy/pocketbase/build-function.py --output uchu-function.zip`
собирает только JS из proxy/, проверяет синтаксис, локальные require и загрузку
точки входа. Корневой ZIP пересобран: 10 модулей, включая accounts-backend.js.
Сборка не меняет env и не разворачивает функцию. Загрузку новой версии и
проверку реальной оплаты выполняем после подготовки PocketBase/приёмки.
