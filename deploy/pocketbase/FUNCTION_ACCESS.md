# Доступ для обновления облачной функции

Codex собрал и проверил ZIP с 10 JS-модулями функции и подготовил diff переключения
кабинета с возможностью отката. На VPS есть доступ; к управлению Cloud Functions
доступа нет. SMTP и S3-ключи разрешают отправку писем и копии — они не дают
изменять облачную функцию. Рабочий сайт ещё не переключён.

Чтобы Codex выполнил обновление сам, нужен отдельный временный сервисный аккаунт.
Это действие вашего облачного аккаунта. Код и команды самостоятельно запускать не надо.

1. Открыть https://console.yandex.cloud/ → ваш каталог **default** →
   **Identity and Access Management → Сервисные аккаунты → Создать сервисный аккаунт**.
   Имя: **uchu-function-deploy**. Если такой аккаунт уже существует, использовать его.
2. В каталоге **default → Права доступа → Настроить доступ → Сервисные аккаунты**
   выбрать **uchu-function-deploy**. Добавить две роли:
   **functions.editor** и **iam.serviceAccounts.user**. Сохранить.
   Роли назначаются на этот каталог, не на всё облако. Общие editor/admin не нужны.
   Первая роль позволяет обновить функцию и прочитать её текущую конфигурацию;
   вторая нужна для сохранения привязанного к ней runtime-сервисного аккаунта.
3. Вернуться в **IAM → Сервисные аккаунты → uchu-function-deploy**.
   **Создать новый ключ → Создать авторизованный ключ → Создать**.
   Сохранить результат в JSON-файл через кнопку скачивания/сохранения ключа.
   Нужен авторизованный ключ JSON; это отдельный тип доступа, не статический S3
   и не API-ключ Postbox. Его не нужно перепечатывать вручную.
4. Прикрепить скачанный JSON-файл в текущий чат Codex. В пульт его загружать
   не требуется. Так Codex сможет сам прочитать текущую конфигурацию функции,
   сохранить исходную версию для отката, подготовить обновление с сохранением
   действующих AI/платёжных настроек и проверить связь с PocketBase.
5. После завершения работ отозвать временный ключ/роли в своём аккаунте Яндекса.

Обновление функции ещё не выполнено. Настоящие входы, оплата и юридические
документы пока не приняты. Само получение ключа не означает завершение переноса.

Официальные инструкции (проверены 12.11.2026):
https://yandex.cloud/ru/docs/iam/operations/sa/create
https://yandex.cloud/ru/docs/iam/operations/sa/assign-role-for-sa
https://yandex.cloud/ru/docs/iam/operations/authentication/manage-authorized-keys
https://yandex.cloud/ru/docs/functions/security/

ZIP без секретов: pocketbase-function.zip. Сборка проверена загрузкой entrypoint
и синтаксисом всех модулей; при публикации необходимо сохранить текущую память,
таймаут, сервисный аккаунт, остальные переменные и связанные ресурсы.
