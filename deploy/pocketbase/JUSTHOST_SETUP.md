## Почта и внешние приложения

Почта, Яндекс и Google обязательны; SMS не нужен.
Пошаговые действия владельца: https://uchu-rf-setup-guide.keenlarch65.chatgpt.site/.

- Яндекс: существующее приложение `f3205940304e48d9a3243d85fd3c9c73`,
  callback `https://uchu-po-frp.ru/yandex.html`; требуется Client Secret.
- Google: владелец сообщил о настройке Web application; Client ID получен.
  Origin `https://uchu-po-frp.ru`,
  callback `https://uchu-po-frp.ru/google.html`; требуется защищённое внесение Client Secret.
- SMTP: сначала уже имеющийся ящик. Для Mail.ru нужен отдельный пароль приложения
  с правом только отправки; обычный пароль аккаунта не использовать.
  Официально: https://help.mail.ru/mail/login/mailer/.
  `smtp.mail.ru`, порт 465, SSL/TLS, логин — полный адрес ящика.

Секреты вносятся только в закрытые серверные настройки через защищённый доступ;
в чат, START.html, index.html и GitHub их не вставлять. Если защищённый способ
передачи ещё не подключён, сначала согласовать его без отправки самих секретов.
Реальные OAuth-входы, письма, AI, платежи и переключение требуют отдельной приёмки.

## Закрытый ввод секретов без отправки в чат

Codex запускает `enter-oauth-secrets.py` в консоли VPS с уже полученными публичными
Client ID. Владелец вводит только Yandex Client Secret, затем Google Client Secret
в скрытые getpass-поля; запускать команды владельцу не требуется. Не вводить
секрет, если на экране нет точной строки `YANDEX CLIENT SECRET (hidden):`
или `GOOGLE CLIENT SECRET (hidden):`. При ошибке не повторять ввод в shell prompt.
Скрипт не выводит значения, сохраняет root:600 атомарно, не включает вход/регистрацию.
Настройки становятся доступны службе после завершения обоих полей и её перезапуска.
Технический успех сохранения не заменяет настоящие OAuth-входы и привязку.
