# Кабинеты: персональные данные и удаление

## Что реализовано

- Основные данные кабинета обрабатываются для договора; оферта принимается отдельно.
- Имя, школа, город, фото — отдельное добровольное согласие. Без него кабинет работает.
- Email, Google и Яндекс: сервер проверяет версию условий до создания аккаунта.
- Квитанции содержат ID, время, метод и SHA256 неизменяемых снимков документов; IP для этого не добавляется.
- Настройки: полная копия данных JSON; ZIP исходников, изображений и Word; отзыв необязательного профиля.
- Удаление: 8 цифр на подтверждённую почту, 10 минут, 5 попыток, одна учётная запись, транзакция.
- Удаляются рабочие данные, привязки, роль администратора, собственные общие материалы и локальные архивы этого кабинета.
- Незавершённый платёж требует сверки до удаления, чтобы не потерять деньги; остальные данные не откатываются автоматически.
- Для запрета повторного пробного доступа — HMAC почты/внешних ID, отдельный приватный ключ, до трёх лет после удаления.
  Удалённые документы не возвращаются в новый аккаунт. Gmail-точки и +метки нормализуются только для антифрода,
  не для автоматического объединения кабинетов. Определить одного человека по произвольным разным адресам невозможно.
- Публичная библиотека не возвращает служебную почту автора; авторство хранится в закрытой серверной колонке.
- Шрифты размещены локально. Canvas/WebGL-отпечаток больше не вычисляется. Случайный ID устройства и сетевой счётчик сохраняются.
- Результаты тестов запрашивают условный код вместо ФИО. Псевдонимизация не отменяет необходимости определить права детей и основания обработки.

## Перенос проверенной версии на существующий VPS

`upgrade.py --ref <полный SHA>` проверяет SHA256 источников из release.json, создаёт зашифрованную
копию, проверяет миграцию на настоящей приватной копии БД (loopback 8093), затем обновляет основной
backend без замены пользовательских записей старым снимком. Добавляет отдельный HMAC-ключ и
проверяет свежую S3-копию реальным скачиванием, расшифровкой и SQLite integrity_check.
Не применять install.sh к существующему VPS и не повторять уже принятую миграцию вслепую.

## Удаление и восстановление

- Транзакция удаления включает secure_delete для SQLite writer; журналы и ограниченные копии
  остаются в изолированном доступе, а не выдаются новому пользователю.
- После удаления ставится флаг для свежего проверенного offsite snapshot. Удаления объединяются:
  не более одной дополнительной копии в час; при ошибке задача повторяется. Ночной backup сохраняется.
- Каждая копия содержит приватный подписанный журнал удалений и HMAC-защиты. Подпись не содержит ключ.
- Подготовленные восстановления помечаются `.privacy-review-required`. Systemd не запускает такой
  PocketBase до сверки с последним независимым журналом, применения удалений и защиты пробного доступа.
- Не считать журнал внутри старого снимка последним: берётся журнал из последней проверенной независимой
  копии/действующего сервера. При неопределённости о новых удалениях доступ не открывать до проверки оператором.

Оператор в терминале на VPS (ключи не выводятся):

```bash
/usr/local/sbin/uchu-privacy-ledger export --database /var/lib/pocketbase/data.db --key-file /etc/pocketbase/pocketbase.env --ledger /root/latest-privacy-ledger.json
# Восстановить снимок только в новую закрытую папку, выполнить matching forward migrations.
/usr/local/sbin/uchu-privacy-ledger apply --database /root/restored/var/lib/pocketbase/data.db --key-file /etc/pocketbase/pocketbase.env --ledger /root/latest-privacy-ledger.json
```

`apply` отказывается менять живую БД, проверяет HMAC, удаляет восстановленные кабинеты/роли/данные,
сохраняет других владельцев и возвращает защитные отметки. Только затем снимается маркер.
Если ключи были утрачены, требуется отдельная сохранённая age-копия ключа владельца; без неё
расшифровка не обещается. Ротацию HMAC-ключа нельзя выполнять без плана переноса защитных отметок.

## Что не заменяется кодом

Уведомления и подпись РКН, точные сведения о ЦОД/контрагентах из договоров, решения о трансграничных
потоках Google/иностранных AI/прежнего Supabase, организационная оценка угроз, исполнение обращений
и порядок работы с данными детей. Уровень защищённости/сертификация не объявляются автоматически.
Политика описывает фактические меры и ограничения; полного юридического заключения этот комплект не выдаёт.
