# Аккаунты и персональные данные на отдельном аккаунте

## Архитектура

- **Яндекс Облако** — остаётся: статический сайт в Object Storage и AI-прокси.
- **Аккаунты и персональные данные** — отдельный проект **Supabase** (другой
  аккаунт/организация), а не тот, что используется для статики.
- Сайт хранит в Supabase:
  - пользователей и сессии;
  - профили;
  - уроки;
  - результаты тестов;
  - материалы;
  - промокоды/тарифы, если нужно.

В Яндекс-облаке **не должно быть базы с персональными данными**. Функция может
быть stateless-прокси, но данные пользователей — только в отдельном Supabase.

## Что уже добавлено в код

В `index.html` появился отдельный блок:

```js
accounts: { url: "", anonKey: "", dashboard: "" },
```

Пока он пустой — сайт использует старый `cloud`. Как только вы заполните
`accounts.url` и `accounts.anonKey`, личный кабинет, профили, уроки и quiz
переключатся на отдельный проект.

Логика выбора:

```js
const C = () => {
  const a = window.UCHU_SITE?.accounts;
  return (a && a.url && a.anonKey) ? a : (window.UCHU_SITE?.cloud || {});
};
```

## Шаги подключения

1. Создать **отдельный аккаунт Supabase** (не тот, где сейчас `cloud`).
2. Создать проект, например `uchu-accounts`.
3. Выполнить SQL из репозитория:
   - `supabase.sql` — основные таблицы;
   - `supabase_security.sql` — RLS;
   - `supabase_quizzes.sql` — тесты;
   - остальные `supabase_*.sql` по необходимости.
4. Настроить Auth:
   - email + пароль;
   - при необходимости телефон/SMS;
   - SMTP;
   - redirect URL — адрес сайта.
5. В `index.html` заполнить:
   ```js
   accounts: {
     url: "https://<новый-проект>.supabase.co",
     anonKey: "<anon public key>",
     dashboard: "https://supabase.com/dashboard/project/<id>"
   }
   ```
6. В настройках Yandex-функции заменить `SUPABASE_URL` и `SUPABASE_SERVICE_KEY`
   на новый проект, если функция использует их для лимитов/платежей.
7. Проверить:
   - вход;
   - регистрация;
   - восстановление пароля;
   - сохранение урока;
   - RLS: чужой урок недоступен.

## Управление аккаунтами

В Supabase Dashboard:

- **Authentication → Users** — список пользователей, сброс пароля, блокировка,
  удаление;
- **Table Editor → profiles** — профили;
- **SQL Editor** — массовые операции;
- **Logs** — ошибки входа.

Это и есть «сайт для ведения аккаунтов»: сайт — витрина и кабинет, Supabase —
админ-панель пользователей.

## Если нужен 152-ФЗ

Облачный Supabase — не РФ. Для хранения персональных данных в РФ:

- развернуть **self-hosted Supabase** на российском VPS (Timeweb, Beget,
  Selectel) в отдельном аккаунте;
- поставить HTTPS;
- заполнить `accounts.url` адресом своего Supabase;
- перенести данные и проверить RLS.

Яндекс Облако при этом остаётся для статики и AI-прокси, но не хранит ПДн.

## Важно

- Не хранить `service_role` ключ в `index.html` или в браузере.
- Публичный ключ — только `anon`.
- RLS включать на всех пользовательских таблицах.
- Перед сменой проекта сделать резервную копию.
