# Аккаунты, персональные данные и 152-ФЗ

## Коротко

- **Облачный `supabase.com` нельзя использовать для персональных данных
  граждан РФ** как основную базу: его инфраструктура находится за пределами РФ,
  а 152-ФЗ требует записи ПДн в базы, расположенные в России.
- **Self-hosted Supabase** на российском сервере — можно. Это не сервис
  `supabase.com`, а открытый набор компонентов (PostgreSQL, GoTrue, PostgREST,
  Storage, Studio), который вы разворачиваете сами в РФ.
- **Яндекс Облако** остаётся: статика и AI-прокси. Персональные данные там
  храниться не должны.

## Два допустимых варианта

### Вариант A — self-hosted Supabase на российском VPS

Подходит, потому что сайт уже написан под API Supabase, менять код почти не нужно.

- VPS в РФ: Timeweb, Beget, Selectel, Cloud.ru.
- Docker Compose с Supabase.
- Свой домен и HTTPS, например `https://supa.uchu-po-frp.ru`.
- PostgreSQL, Auth, Storage, Studio — всё на вашем сервере.
- Резервные копии — в РФ.
- В `index.html`:

```js
accounts: {
  url: "https://supa.uchu-po-frp.ru",
  anonKey: "<anon key>",
  dashboard: "https://supa.uchu-po-frp.ru"
}
```

Плюсы: код сайта не переписывать, данные в РФ, аккаунты ведутся в Studio.
Минусы: сервер нужно обслуживать и делать бэкапы.

### Вариант B — Yandex Managed PostgreSQL + своя авторизация

- PostgreSQL в Яндекс Облаке, в отдельном аккаунте.
- Auth — свой API: регистрация, вход, SMS, сессии.
- Сайт обращается к вашему API, а не к Supabase.
- Плюсы: полностью российская инфраструктура, управляемый PostgreSQL.
- Минусы: нужно переписать `account.js` и часть `access.js`, больше кода.

## Что нельзя

- Хранить ПДн в `supabase.com` (AWS) и считать, что достаточно «другого аккаунта».
- Держать `service_role` ключ в браузере.
- Писать «данные в РФ», если база фактически за границей.
- Использовать зарубежный Supabase только потому, что он удобнее.

## Что уже есть в коде

В `index.html` добавлен блок:

```js
accounts: { url: "", anonKey: "", dashboard: "" },
```

Пока он пуст — работает старый `cloud`. После заполнения личный кабинет,
профили, уроки и тесты переключатся на указанный адрес.

Подойдёт и self-hosted Supabase, и любой совместимый PostgREST-сервер.

## Порядок переноса

1. Поднять self-hosted Supabase на российском VPS.
2. Выполнить SQL:
   - `supabase.sql`;
   - `supabase_security.sql`;
   - `supabase_quizzes.sql`;
   - остальные по необходимости.
3. Настроить Auth: email, при необходимости SMS, SMTP, redirect URL.
4. Заполнить `accounts` в `index.html`.
5. В Яндекс-функции заменить `SUPABASE_URL` и `SUPABASE_SERVICE_KEY` на новый
   адрес, чтобы лимиты и платежи работали с РФ-базой.
6. Проверить вход, сохранение урока, RLS, удаление аккаунта.
7. Сделать бэкап и проверить восстановление.

## Что нужно от владельца

- Российский VPS или аккаунт в российском облаке.
- Домен/поддомен для Supabase.
- Доступ к DNS.
- Решение: вариант A (быстрее) или B (полностью свой auth).
