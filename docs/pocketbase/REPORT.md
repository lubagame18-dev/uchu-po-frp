# Кабинеты на PocketBase: отчёт локальной подготовки

07.11.2026. Ветка codex/pocketbase-accounts, основана на codex/rf-migration.
Git на старте был чистым. Изучены AGENTS.md, текущий кабинет, запросы proxy,
quiz-страниц и предыдущий комплект миграции.

## Граница изменения

PocketBase — только аккаунты, профили, уроки/результаты и данные тарифов. Статика,
GitHub-деплой и AI-прокси остаются в Яндексе. Хостинг PocketBase не выбран и платные
ресурсы не создавались. Скриншот владельца показывает Object Storage/Cloud Functions,
DNS и сеть; наличие отдельной VM по нему не установлено. Реального доступа к исходной
БД и новому серверу нет, поэтому данные с сайта НЕ ПЕРЕНЕСЕНЫ.

## Изменено

- deploy/pocketbase/: закреплённый бинарник с checksum, схема закрытых коллекций,
  ограниченный адаптер Auth/REST/RPC, транзакционные payment/quota операции,
  export/import с dry-run, guards переключения, backup/restore, серверный launcher.
- js/accounts-config.js по умолчанию null: PocketBase выключен.
- js/accounts-backend.js и account.js: опциональный transport, обновление сессий,
  запрет fallback на старую БД, защита локальных черновиков при смене владельца.
- Исправлен выход из кабинета: Store.clear требует имя store; старый код вызывал
  его без аргумента через несуществующий window.Store. Теперь выполняется реальная
  очистка после проверенной локальной копии. Архив отделён от очищаемой БД.
- Добавлена выдача только своего архива уроков; материалы того же владельца
  восстанавливаются после повторного входа, чужие данные не отправляются в новый аккаунт.
- accounts-confirm.html: подтверждение и recovery без открытой админки; токен удаляется
  из адресной строки, referrer отключён, пароли/токены не пишутся в логи.
- proxy/accounts-backend.js и связанные account-запросы: серверный переключатель.
  Маршруты AI и платёжного провайдера сохраняют адреса. PocketBase webhook использует
  сохранённый заказ и атомарно фиксирует баланс + paid. Повтор не начисляет повторно.
- В test/ и taras-bulba/ изменены только технические подключения cloud config;
  учебные тексты и генератор не изменялись.
- Новый workflow запускает изолированные проверки без секретов и внешних сервисов.

## Что блокирует рабочее переключение

1. Нужны постоянный процесс/диск для PB, HTTPS и защищённый доступ. Хостинг не выбран.
2. Подключить настоящий SMTP, проверить реальную доставку/восстановление.
3. Проверить фактическую исходную БД. Владелец сообщил, что пользователей нет,
   но это не заменяет инвентаризацию. Непустые users требуют согласованного reset-плана;
   хеши старых паролей автоматически не импортируются.
4. SMS, Яндекс/OAuth, bot magic links, автосписания и legacy quiz без ID требуют
   отдельной реализации/приёмки или явного решения владельца об отключении.
5. Собрать актуальный ZIP Яндекс-функции, проверить env на target и sandbox платежи.
6. Выполнить remote backup/restore и все acceptance gates, затем review и переключение.

Рабочие UCHU_SITE.accounts/cloud, секреты функции и размещённый сайт не переключались.
Старый Supabase и предыдущий комплект сохранены. Основной код предлагается черновиком;
невыполненные сценарии не помечаются завершёнными.
