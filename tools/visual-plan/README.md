# visual-audit — аудит визуальных планов

Zero-dependency CLI, который прогоняет движок `VisualPlan` (`js/visualplan.js`)
по **всем** урокам из `data/frp2025/*.js` и доказывает, что ни один слайд не
остаётся без валидного визуального плана.

Актуальные числа и примеры планов — в `tools/reports/visual-audit.md`
(и машинно-читаемый `tools/reports/visual-audit.json`).

## Требования

- Node.js 24 (`node` в PATH), внешние пакеты не нужны.
- Готовый движок `js/visualplan.js` (UMD, без DOM). Без него аудит завершится
  с exit code 1: демо-движок для приёмки не используется.

## Запуск

Из корня репозитория:

```bash
node tools/visual-audit.mjs --limit 50
node tools/visual-audit.mjs
node tools/visual-audit.mjs --subject bio --out tools/reports
```

CLI:

| Флаг | Значение |
|---|---|
| `--limit N` | проверить только первые N уроков (детерминированный порядок) |
| `--subject <код>` | только один предмет (`bio`, `math`, `hist`, …) |
| `--out <dir>` | каталог отчётов; по умолчанию `tools/reports` (относительно корня репозитория) |

Exit code: `0` — все критерии выполнены, `1` — есть нарушения, ошибки движка,
превышен лимит времени или не найден `js/visualplan.js`.

## Что проверяется

1. Данные загружаются через `node:vm` с заглушкой `window` (без DOM) из всех
   `data/frp2025/*.js`. Поддерживаются оба формата: `window.FRPPlans2025`
   (`{s, l, th, src}`) и `window.UCHU_FRP_PLANS2025` (`{topics:[…]}`, файл `lit.js`).
2. Уроки — это уникальные пары «предмет + класс + тема» (тема берётся из `l[][0]`
   или `topics[].title`), дубликаты внутри программы схлопываются.
3. Для каждого урока строятся 6 синтетических слайдов: титульный, цели,
   три содержательных и итог. Факты берутся из тематического блока `th`
   (содержание и требования), при отсутствии — из темы и раздела.
4. Каждый слайд проходит `VisualPlan.planForSlide`, затем `VisualPlan.validate`.
   Дополнительно аудит независимо проверяет: пустой план, пустой `image_prompt`,
   кириллицу и цифры в промпте, упоминания карт в промпте и `editorial_check`.
5. Жёсткие критерии приёмки (любое значение > 0 — FAIL):

   - `EMPTY_SLIDE`, `NULL_PROMPT`, `MAP_REQUEST`, `PROMPT_CYRILLIC`,
     `PROMPT_DIGITS`, все `SVG_*`;
   - каждый урок даёт хотя бы один валидный слайд;
   - `PORTRAIT_VIA_FLUX` = 0 (критическое правило контракта);
   - **все** нарушения любого кода валидатора = 0 (включая новые коды QA:
     `FAKE_PORTRAIT`, `WIKI_TITLE_IMPLAUSIBLE`, `FAKE_REPRO`);
   - аудит укладывается в 120 секунд.

6. Собирается статистика: число уроков и слайдов, распределение 5 стратегий
   и доля непустых `image_prompt`, нарушения по кодам, разрез по формату данных
   (`frp_plans` / `rich_topics`) и три полных JSON-плана.

Ключ дедупликации уроков: `предмет + класс + нормализованная тема` (ведущая
нумерация ФРП снята). Канонический объём: 4447 уроков = 3803 из 18 файлов
`FRPPlans2025` + 644 из `lit.js` (rich-topics, `UCHU_FRP_PLANS2025`).

## Как читать отчёт

`visual-audit.md` — для ревью, `visual-audit.json` — для CI/машинной проверки.
Ключевые поля JSON:

- `criteria.passed` — итог аудита; `false` означает exit code 1;
- `criteria.required_zero` — жёсткие нули по кодам;
- `criteria.all_violations_zero` — сумма всех нарушений любого кода;
- `criteria.qa_new_codes` — нули по новым кодам QA (`FAKE_PORTRAIT`,
  `WIKI_TITLE_IMPLAUSIBLE`, `FAKE_REPRO`);
- `criteria.every_lesson_has_valid_slide` — уроки без валидного слайда (с примерами);
- `strategies` — `{count, percent}` по 5 стратегиям;
- `prompts.non_empty_percent` — доля слайдов с непустым промптом;
- `errors.by_code`, `errors.by_source` и `errors.examples` — нарушения, их источник
  (`validate` движка или независимые проверки аудита) и примеры;
- `plans_examples` — 3 полных плана для быстрого ревью;
- `scope` — предметы, число классов/уроков/слайдов и активные фильтры.

Отчёт детерминирован: без дат, случайных значений и абсолютных путей; повторный
запуск на тех же данных и движке даёт идентичные файлы.

## Самопроверка инструмента (не для приёмки)

Если `js/visualplan.js` ещё не готов, каркас аудита можно проверить на встроенной
демо-заглушке:

```bash
node tools/visual-audit.mjs --limit 50 --demo-engine --out tools/reports/dev
node tools/visual-audit.mjs --limit 60 --demo-engine --demo-fault --out tools/reports/dev-fault
```

`--demo-engine` разрешает встроенную демо-заглушку, если `js/visualplan.js`
отсутствует (при наличии реального движка он всегда используется);
`--demo-fault` вместе с демо-заглушкой добавляет контролируемые нарушения,
чтобы проверить подсчёт ошибок и exit code 1. Оба флага служебные и в приёмке
не используются.
